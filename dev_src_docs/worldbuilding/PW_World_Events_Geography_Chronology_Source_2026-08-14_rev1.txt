1. PURPOSE

Add a robust temporal-reference layer to the Post-PANDORA / World War III geography
map without inventing calendar precision that the canon has not yet locked.

The owner intends the map eventually to carry timestamps for all narratively significant
world events. This revision begins that work now by:
- landing exact canon calendar anchors already locked in controlling sources;
- adding a 133-row chronology sidecar keyed to stable PW-GEO identities;
- binding selected mapped features to exact anchors or protected relative windows;
- leaving unresolved feature dates explicitly unresolved;
- reserving direct KML TimeStamp/TimeSpan injection into existing spatial placemarks
  for the point when each feature's own onset/date/range is source-locked.

3. WHY EXISTING SPATIAL FEATURES DO NOT YET RECEIVE DIRECT TIMESTAMPS

The current 133 PW-GEO features include locations, operational corridors, battles,
blockades, occupation polygons, and persistent territorial-control states.

A locked theater date is not automatically the onset date of every polygon inside that
theater. For example, Game 1 locks September 7, 2028 as the day coordinated hostile
offensives begin along the West Coast. That fact may anchor the Pacific Northwest,
Iranian Bay Area, DPRK Southern California, and Seattle/Puget geography. It does not
prove that each blockade or occupation polygon had already reached the exact state or
extent drawn on the map on September 7.

Accordingly this revision adds no direct TimeStamp/TimeSpan primitive to the original
133 spatial placemarks. That is deliberate source discipline, not missing work.

7. SOURCE SAFEGUARDS

- September 7, 2028 is the canonical PANDORA date. Older September 3, 2028 variants are stale.
- November 7, 2028 is the canonical election date. Older November 3/6 variants are stale.
- Do not convert "approximately one month into occupation," "after Game 1," "before Game 2,"
  or mission-order relationships into exact calendar dates.
- Do not use a theater-offensive start as the automatic begin date of an occupation/control polygon.
- Do not give a persistent territorial state a TimeStamp when a TimeSpan is eventually required.
- Do not add a TimeSpan end boundary unless the end of that represented state is independently source-locked.
- Stable PW-GEO identities must survive later chronology enrichment.

8. NEXT-PASS MODEL

Future chronology work should proceed incrementally:
1. When an event receives a locked exact date, add/upgrade its PW-TIME anchor.
2. Bind all corresponding PW-GEO features.
3. If the mapped feature itself represents the dated event, inject TimeStamp.
4. If the mapped feature represents a persistent state with locked start/end, inject TimeSpan.
5. Preserve relative-only bindings where calendar precision remains intentionally open.

This allows the world-events map to mature into a chronological GIS layer without
back-filling false precision merely to make the time slider look complete.
