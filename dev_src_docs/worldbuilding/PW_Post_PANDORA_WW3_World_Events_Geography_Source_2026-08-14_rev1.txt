4. SOURCE AUTHORITY MODEL

The map is authoritative for spatial reference at the level actually drawn and labeled.
It is not automatic authority for details that the KML does not state.

Use the following hierarchy:

A. EXISTING NARRATIVE SOURCE + MAP GEOGRAPHY
Where a durable narrative source already defines the event, mission, faction, or campaign,
that source controls narrative meaning. This map adds or refines geography.

B. EXISTING EVENT WITH PREVIOUSLY OPEN GEOGRAPHY
Where an existing source deliberately left exact geography open and this map now supplies
a location, route, footprint, or territorial boundary, the later owner-provided map may
resolve that geographic field while leaving unrelated open fields untouched.

C. MAP-ORIGINATED WORLD-EVENT OR WORLD-STATE CLAIM
Some placemarks identify battles, strikes, occupations, blockades, pockets, campaigns,
or territorial-control states that do not yet have an equally specific dedicated narrative
source page. Those entries are valid map-level worldbuilding references and should be
retained in the ontology geography registry. They must not be silently expanded into
dates, orders of battle, mission ladders, casualty totals, or playable content that the
map does not provide.

D. REFERENCE-ONLY GEOMETRY
Unnamed placemarks, supporting points, and unlabeled overlays remain geographic evidence.
Do not invent names or narrative functions merely to make the registry look complete.

10. GEOGRAPHY ONTOLOGY RULES

The geography ontology is additive and separate from the chronological world-event graph.

A geographic feature may be:
- a point;
- a line / operational corridor;
- a polygon / territorial-control or event footprint;
- a reference-only anchor.

Each feature receives a stable PW-GEO-* identity in the registry.

The geography registry may point toward an existing PW-EVT-*, PW-TRK-*, or PW-CMP-* entity
when the relationship is source-supported. A geographic identity does not automatically
create a new timeline event.

The KML remains the authoritative carrier for detailed geometry. The YAML ontology records:
- stable feature identity;
- placemark ordinal;
- label;
- geometry type;
- feature role;
- source stage;
- bounding box;
- centroid;
- source description;
- known repo cross-reference;
- ontology treatment.

Do not duplicate the full KML coordinate arrays into the timeline ontology.
